# CLI Updater

Herdr 없이도 실행하는 로컬 CLI 관리 화면입니다. **업데이트(Updates)**에서 설치와 최신 조회 결과를 비교하고, 확인창에서 바뀌는 버전을 보고 업데이트합니다. **터미널 세션(Terminal sessions)**과 **기록(History)**에서 실행 상태와 작업 결과를 따로 확인합니다. 초기 원본 설치 검증 대상은 macOS의 Bun 전역 OmO였으며, 현재 카탈로그 업데이트 가능 여부는 설치별 출처 검증으로 결정합니다.

관리 지원 범위는 **OmO, Pi, OMP, OpenCode, Claude Code, Codex, GJC** 7종입니다.
나머지 herdr 세션은 **터미널 세션**에서만 `아직 지원하지 않음`으로 표시하며,
설치 관리·최신 조회·업데이트·자동 업데이트·재시작을 제공하지 않습니다.
기존 CLI 설치와 대화는 삭제하지 않습니다. 기존 미지원 CLI 자동화도 실행하지 않습니다.

지원 ID는 `claude`, `codex`, `gjc`, `omp`, `omo`, `opencode`, `pi`입니다.
Pi는 원본 **`@earendil-works/pi-coding-agent`**입니다. 기존 standalone Senpi를 Pi로
재명명·교체·삭제하지 않으며 설치와 대화 기록은 보존합니다. OmO에 포함된 Senpi는
OmO 엔진으로 구분합니다. 원본 Pi, OpenCode, GJC의 동일 대화 재시작은 제공하지 않습니다.

**업데이트 → CLI 상세**에서 업데이트 대상, 설치 관리, 자동화를 확인합니다.
**CLI 추가**는 업데이트 화면에서 열며, 한 설치의 제거와 여러 설치의 통합은 별도 확인창에서 실행합니다.
업데이트 대상 선택은 새 터미널의 기본 실행 경로 변경과 다릅니다.
앱 소유 설치, npm/Bun 전역 설치, Homebrew 및 공식 설치는 각각 구현된 출처·경로 검증을
통과해야 합니다. 목록에 포함되거나 최신 조회에 성공했다고 업데이트·제거 권한이 생기지 않습니다.
출처 미확인·플랫폼 미지원은 이유와 공식 안내로 남습니다. Windows 네이티브는 미지원이며 WSL2는 Linux 환경만 관리합니다.

## 설치와 실행

Bun 1.4.2 이상과 Node 24 이상이 필요합니다. 관리 대상 CLI의 전역 폴더와 분리된 전용 폴더에 설치합니다.

```sh
mkdir -p "$HOME/.local/share/cli-updater-app"
bun add --cwd "$HOME/.local/share/cli-updater-app" /absolute/path/herdr-cli-updater-0.2.0.tgz
export PATH="$HOME/.local/share/cli-updater-app/node_modules/.bin:$PATH"
cli-updater
```

브라우저가 열리고 로컬 서비스는 백그라운드에서 유지됩니다. 브라우저를 닫아도 진행 중인 작업이나 설정한 자동 확인은 취소되지 않습니다. 현재 npm 레지스트리에 게시한 패키지는 아니므로 위 명령에는 전달받은 파일의 실제 경로를 사용합니다.

`PATH` 설정을 셸 설정 파일에 유지하거나 전용 폴더의 `node_modules/.bin/cli-updater`를 직접 실행합니다. 앱 tarball을 OmO와 같은 Bun 전역 폴더에 설치하면 Bun이 업데이트 중 앱까지 다시 추출할 수 있어 원본 변경 범위 검증이 거부합니다.

```sh
cli-updater --no-open           # 브라우저 대신 접속 주소 출력
cli-updater status             # 로컬 서비스 상태
cli-updater stop               # 작업을 끊지 않는 정상 종료
cli-updater serve              # 포그라운드 실행
cli-updater --help
```

데이터 기본 경로는 `~/.local/share/cli-updater`입니다. 다른 경로는 `--state-dir /absolute/path`로 지정합니다. 웹 서버는 `127.0.0.1`에만 바인딩합니다. 처음 출력된 주소는 일회용 인증 주소입니다. 승인된 브라우저는 같은 주소와 상태 폴더에서 최대30일간 인증을 유지하며, 서비스 재시작만으로 만료되지 않습니다. 새 브라우저·기간 만료·다른 포트에서는 `cli-updater open`으로 새 접속 창을 엽니다.

## 동작 범위

- **설치**: 설치 버전, 조회한 최신 버전과 조회 시각, 실제 검증된 설치 결과를 구분합니다. 조회·준비만으로 설치를 바꾸지 않습니다. 카탈로그 실행은 조회 버전에 고정하지 않고 실행 시 공식 배포처의 최신 버전을 설치한 뒤 실제 결과를 검증합니다. 확인창을 연 뒤 대상·출처·서비스·작업 revision이 바뀌면 닫고 다시 열어야 합니다.
- **관리 세션**: 이 서비스가 직접 실행한 OmO만 종료·재시작합니다. 작업과 승인이 진행 중이면 대기합니다. 원본 RPC의 안전한 해제 결과, 실제 프로세스 종료, 재실행 후 대화 식별자를 확인합니다.
- **외부 실행**: 현재 사용자의 OmO·OMP·Pi·Claude·Codex CLI를 실행 위치로 식별하고 터미널·시작 시각을 관측합니다. 15초마다 목록을 갱신하며 관측 실패는 마지막 성공 시각과 함께 표시합니다. 설치와 연결할 수 없거나 실행 버전을 증명할 수 없으면 미확인으로 남기고 제어하지 않습니다.
- **전체 업데이트**: 검색 필터와 관계없이 설치된 전체 카탈로그를 조회·준비하고 별도 승인으로 실행합니다. 항목별 성공·실패·미확정·제외 이유를 유지하며 성공 항목을 재실행하지 않습니다. 이 경로는 세션을 유지합니다.
- **업데이트 기록**: 설치 성공을 검증한 결과와 세션 재시작 결과는 별개입니다. 응답 유실·서비스 재시작은 성공으로 추정하지 않습니다. **재설치 없이 결과 재확인**은 설치 명령 없이 출처와 디스크 버전을 확인합니다. 과거 실행 근거가 부족하면 미확정으로 남습니다. 재확인 근거와 실행 중 설치 작업이 없음을 검증한 뒤 **성공 미확인으로 보관**할 수 있으며, 이는 `archived-unverified`이지 성공이 아닙니다. 재연결·새로고침은 설치를 재전송하지 않습니다.
- **자동화**: 새 정책은 세션 유지가 기본입니다. 카탈로그 자동화는 켜면 바로, 이후 기본 1시간 간격으로 조회하고 새 버전이 있을 때만 실행합니다. 최신·더 높은 설치 버전·비교 불가·조회 실패는 설치를 시작하지 않습니다. 기존 명시적 세션 정책은 유지되며, 과거 `paneSessions` 누락 정책은 기존 `restart-idle` 의미를 유지하고 화면에서 확인할 수 있습니다. 기존 정책까지 모두 세션 유지라고 가정하지 마세요.

설치 버전, 세션 실행 당시의 OmO 버전, 실제 엔진 버전은 서로 다른 값입니다. 업데이트해도 기존 프로세스의 버전을 새 버전으로 바꿔 표시하지 않습니다.

설치 업데이트 완료는 새 프로세스나 동일 대화 재개 완료를 뜻하지 않습니다. 재시작은 지원되는 관리 세션/검증된 herdr pane에서만 실행하며, herdr 밖 세션이나 지원 근거가 없는 세션에는 제공하지 않습니다.

문제가 생기면 **조회 실패 이유 → 선택 설치의 경로·출처 → 기록의 실제 결과 → 세션 실행 근거** 순서로 확인하세요. 미확정 작업은 설치를 반복하지 말고 기록에서 읽기 전용 재확인을 먼저 실행합니다. 직접 확인할 때는 업데이트 확인창을 열고 ‘자세히’의 대상·출처·설치/조회 버전을 대조한 뒤 취소해도 설치가 바뀌지 않는지 확인합니다. 격리 fixture 검증 방법과 한계는 [web/QA.md](web/QA.md)에 있습니다.

자세한 사용 순서와 복구 범위는 [USAGE.md](USAGE.md)에 있습니다.

## 개발과 패키지 생성

```sh
bun install --frozen-lockfile
bun test
bun run typecheck
bun run build
bun pm pack --destination dist
```

테스트 fixture는 `test/fixtures/evidence/`에 있습니다. Cursor·Antigravity 패키지, codex 바이너리, OmO 배포 아카이브처럼 저장소에 넣을 수 없는 외부 산출물이 필요한 테스트는 산출물이 없으면 `bun test`에서 건너뜁니다. 산출물 폴더를 `CLI_UPDATER_TEST_ARTIFACTS`로 지정하고 `bun run test:artifacts`를 실행하면 모두 실행하며, 산출물이 없으면 빠진 경로와 함께 실패합니다.

런타임 TypeScript와 웹 배포 파일을 함께 패키징합니다. 워커·준비 프로세스의 진입 경로가 이동 후에도 유지되도록 서버 전체를 하나의 번들로 합치지 않습니다. 기존 Herdr 플러그인 진입점은 `scripts/plugin.ts`에 별도로 유지합니다.
