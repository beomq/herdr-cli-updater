# 설치 정리 중심 화면

## 요구와 선택

추가 설치나 공식 설치 이전 버튼보다 기존 설치를 비교하고 남길 사본을 고르는 흐름을 우선한다. `web/catalog.tsx`의 카드는 미설치면 설치, 하나면 관리, 여러 개면 설치 정리로 진입한다. 상세는 팝업 대신 본문에서 표시한다.

`web/catalog-cleanup.tsx`는 남길 설치 선택 → 변경 검토 → 검증·전환 → 사본별 제거 승인 순서다. 자동 업데이트 대상과 터미널 기본 실행은 별도이며, 체크박스는 새 터미널 기본 실행을 함께 바꿀 때만 사용한다. 없는 설치 방식을 추가하는 기능은 보조 영역에 있고 설치 결과가 나오면 정리 화면으로 돌아온다.

## 보호와 한계

- `catalog-select.reviewed`에 경로·실제 실행 경로·버전을 넣는다. `src/app/controller.ts`는 새로 조회한 설치와 비교한 뒤 기존 정책 전환 기능을 호출한다.
- 전환 실패는 제거 단계로 넘어가지 않는다. 제거는 최초 검토의 대상과 현재 제거 가능한 사본으로 제한하고 사본마다 다시 승인한다.
- 실행 중인 사본, 기본 실행, 출처 미확인 설치는 보류한다. 한 사본 제거 성공만으로 통합 완료라 하지 않고 실제 목록에 남길 설치 하나만 있어야 완료로 표시한다.
- 여러 설치를 유지해도 된다. 앱 전용·독립 설치 제거는 파일 보관일 수 있으며 디스크 공간 회수와 다르다.
- 실제 운영 CLI 설치·이전·제거, 터미널 재시작은 이번 검증에서 실행하지 않았다. 구현 검증 당시 미배포였으며, 2026-10-14 사용자의 별도 운영 반영 요청으로 아래 배포를 수행했다.

## 운영 반영 (2026-10-14)

`bun run build` 종료 코드 0 확인 후 공식 `cli-updater stop/open`으로 앱 서버만 교체했다. 서버 PID는 2922에서 24070으로 변경됐고 주소 `http://127.0.0.1:62204`와 상태 저장소는 유지했다. 서비스 `ready`를 확인했으며 현재 대화 PID 86154와 셸 PID 65985는 유지됐다. CLI 설치·삭제 명령은 실행하지 않았다.

## 실행 결과

- `bun test test/app web`: 531개 통과.
- `bun run typecheck`: 종료 코드 0.
- 실제 브라우저용 `Bun.build` production 번들 생성 성공. 운영 `dist`는 덮어쓰지 않았다.
- 격리 API와 실제 웹 화면에서 `catalog-select` → `remove-plan` → 명시적 `remove-confirm` 순서를 확인했다. 마지막 사본 정리 완료, 미확인 사본 추가 시 보류, 전환 실패 시 제거 버튼 없음도 확인했다.
- 1440px 데스크톱과 390px 모바일, 라이트·다크 화면을 직접 확인했다. 비교 목록·검토 화면의 겹침 및 가로 넘침이 없었다.
- 기존 SSR `useLayoutEffect` 경고는 남아 있다. 테스트 통과는 사용자의 이해 확인이나 운영 이전 성공을 뜻하지 않는다.

## 직접 확인과 장애 확인 순서

배포 뒤 CLI 설치 → 여러 설치가 있는 카드의 설치 정리 → 남길 설치 선택 → 변경 내용 검토 순서로 확인한다. 체크박스를 켜지 않으면 터미널 기본 실행은 유지한다. 전환 후에도 각 사본의 제거 승인을 누르기 전에는 삭제하지 않는다.

전환이 막히면 최신 설치 목록·버전, 진행 중/결과 불명 작업, 자동 업데이트 대상과 기본 실행 표시, 작업 기록 순서로 확인한다. 제거가 보류되면 실행 중 세션, 기본 실행, 출처 및 설정 참조를 확인한다.
