# 공식 설치와 단일 업데이트 대상

사용자 승인: CLI 파일을 업데이터 내부에 설치하지 않고 공식 설치 도구로 관리한다.
복수 설치는 유지할 수 있으며 CLI별 자동·전체 업데이트 대상은 하나다. 기본 셸 실행은
별도 선택한다. 기존 설치 삭제나 실행 중 세션 재시작은 전환에 포함하지 않는다.

## 변경

- `catalog-official.ts`: npm/Bun 실제 전역 경로, Devin macOS 공식 Homebrew cask,
  검증된 공식 독립 설치 스크립트. 앱 내부 prefix와 기존 목적지 덮어쓰기 거절.
  새 설치가 기존 PATH 기본 명령을 가리는 경우도 사전 거절한다.
- `catalog.ts`: 공식 설치 계획을 승인하고 실제 버전·설치 탐지를 검증한 뒤에만
  관리 대상으로 채택한다. 실패 시 기존 선택을 유지하며 새 파일은 임의 삭제하지 않는다.
  과거 앱 전용 설치 기록은 읽고 복구할 수 있지만 새 앱 전용 설치 계획은 실행하지 않는다.
- `catalog-default.ts`: 공식 실행 디렉터리를 CLI별 `.zshrc` 블록에 추가한다.
  업데이터 런처를 만들지 않는다. 앱 삭제 후 실행, 실패 복원, 두 CLI의 기본 설정 유지 검증.
- `controller.ts`: 같은 CLI의 경쟁 자동화 정책을 끄고 하나만 유지한다. 선택 변경 시
  기존 자동화 출처를 새 대상에서 검증하고 이전한다. 검증 전에는 선택·정책을 바꾸지 않는다.
  설치 중 자동화 실행을 보류하며 모든 설치/전환과 기존 변경 작업을 직렬화한다.
- `catalog-official-update.ts`: GJC/OMP/Maki/Kimi/OpenCode의 알려진 공식 독립 실행
  파일 경로를 검증해 동일 설치를 업데이트한다. 패키지 설치는 원래 관리자를 유지한다.
- `web/catalog.tsx`: 공식 방식 선택, 출처와 실제 목적지 검토, 기본 실행 별도 선택,
  레거시 설치 이전, 기존 사본 유지. 전역 설치에는 폴더 전체 보관 기능을 제공하지 않는다.

## 검증 및 한계

전체 앱·웹524개 테스트와 typecheck/build 통과. 기존 SSR Select useLayoutEffect
경고는 이번 변경과 별개로 남아 있다. 실제 운영 CLI 설치/삭제/전환은 실행하지 않았다.
격리 fixture의 실제 화면과 가짜 관리자 프로세스로 검증하며 공개 패키지 설치 성공을
대신 주장하지 않는다. 운영 서비스 재시작·반영은 별도다.
최종 대상 일치 보완 후 관련89개 테스트·타입·빌드도 통과했다. 데스크톱1440px와
모바일390px 라이트/다크에서 공식 방식 선택과 목적지·기본 실행 승인 화면 확인.
모바일 가로 넘침 없음, 취소 후 설치/삭제 승인 명령0건. QA 서버와 브라우저 정리.

일부 공식 스크립트(agy/Grok/Hermes/Kiro)는 프로필 변경·추가 설정·앱 실행을
분리할 공식 옵션이 확인되지 않아 자동 실행 대신 공식 안내를 제공한다. Devin은
macOS Homebrew 경로를 제공한다. Claude의 npm/Bun 대안은 권장으로 표시하지 않는다.
Cursor/Muse 설치 가능과 자동 업데이트 지원은 별개다. 이 제한을 24개 전체 지원으로
표현하지 않는다. 기본 전환은 표준 이름의 실행 파일, 기본 .zshrc의 대화형 zsh 대상이다.
공유 bin 디렉터리의 다른 명령도 PATH 우선순위가 바뀔 수 있다.

공식 근거: https://docs.devin.ai/cli,
https://github.com/Yeachan-Heo/gajae-code/blob/main/docs/install.md,
https://omp.sh/install, https://bun.sh/docs/pm/cli/add.

직접 확인: CLI 상세에서 관리 대상과 PATH 기본을 구분하고, 다른 방식으로 설치를
선택해 목적지·기본 실행 체크를 검토한다. 취소 시 설치가 바뀌면 안 된다. 실패하면
작업 진단 코드 → 선택 설치 경로 → 해당 관리자의 설치 상태 → 실제 버전 순서로
확인한다. 전환 실패 파일을 삭제하거나 성공으로 표시하지 않는다.
