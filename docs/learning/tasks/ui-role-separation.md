# 설치·업데이트·터미널 역할 분리

2026-10-14 사용자가 화면 겹침과 기본 실행 체크박스 의미를 지적한 뒤 역할 분리 구현을 승인했다.

## 변경 이유와 동작

- `web/catalog.css`: 이름과 버튼을 두 열에 배치해 긴 제한 안내가 이름을 압축하던 원인을 제거했다. 카드 안은 이름 → 설치 버튼 → 상태 안내 → 상세 순서의 한 열이다.
- `web/catalog.tsx`: 카드에서 삭제 제어를 제거하고 상세로 이동했다. 설치 방법 선택에서 기본 실행 체크박스를 제거하고 `install-plan`은 항상 `makeDefault: false`를 전송한다. 과거 기본 전환 포함 계획은 새 화면에서 실행하지 않는다.
- `web/catalog-installations.tsx`: 업데이트할 설치, 터미널 실행, 설치 삭제 영역을 구분했다. 터미널용 설치 선택은 업데이트 대상 선택과 별도다. 서비스가 관찰한 PATH와 앱이 새 셸용으로 설정한 경로를 구분하고 불일치를 표시한다.
- `src/app/controller.ts`: 기본 실행 계획이 업데이트 대상과 일치해야 한다는 결합을 제거했다. 실제 설치 존재·경로·버전·자동화 및 작업 충돌 검증은 유지한다.
- `web/catalog-updates.tsx`, `web/app.tsx`: 자동화 화면은 현재 업데이트 대상·주기·확인 시각을 표시하고 대상 변경은 해당 CLI 상세로 연결한다. 설치·삭제·기본 실행 제어를 중복 배치하지 않는다.

## 검증

전체 앱·웹526개 테스트 통과. 마지막 보완 후 관련86개와 타입 검사 통과.
최종 소스로 production Bun.build 성공. 운영 dist를 덮어쓰지 않기 위해 격리 서버에서 메모리 번들을 제공했다.
390px/1440px, light/dark의 카드·설치 선택·터미널 실행·자동화16개 캡처를 확인했다.
모바일 가로 넘침 없음. 설치 요청은 makeDefault:false, 터미널 변경 계획은 별도 qa-npm이며 Bun 업데이트 대상은 유지됐다.
서버 통합 테스트에서는 업데이트 대상으로 선택하지 않은 설치의 기본 실행 전환이 완료되고 기존 대상·정책·두 설치 파일이 보존되는 것을 확인했다.

## 한계와 직접 확인

실제 CLI 설치·삭제·.zshrc 변경·운영 서비스 재시작은 실행하지 않았다. 브라우저 조작은 격리 snapshot/API fixture에서 확인했다.
기존 SSR Select useLayoutEffect 경고는 남아 있고 CSS LSP는 Biome 미설치로 실행 불가다. 타입 진단·번들·실제 렌더는 별도 통과했다.
기본 실행 변경은 기존 제약대로 자동화가 꺼져 있고 결과 미확정 작업이 없어야 한다. PATH 디렉터리 우선순위는 다른 명령에도 영향을 줄 수 있다.
직접 확인은 CLI 설치 → 상세 → 업데이트할 설치/터미널 실행/설치 삭제를 구분하고, 자동 업데이트 탭에서 대상 변경 버튼이 동일 CLI 상세를 여는지 보면 된다. 실패 시 서비스 연결 → 설치 목록/진행 작업 → 선택 경로 → 진단 코드 순서로 확인한다.
