# 대시보드 사용성 개선안

## 확인한 문제

실제 운영 화면과 `web/app.tsx`의 Workspace를 대조했다. 이후 사용자가 구현을 승인해
상태 요약, 다음 행동, 세션·자동화 바로가기, 관찰 묶음 표시를 반영했다.

1. **설치된 CLI의 의미가 다르다.** 카탈로그에서 발견한 Claude·Codex 등의 설치와
   대시보드 업데이트 관리 대상이 별개인데 제목은 둘 다 설치된 CLI로 읽힌다.
   설치가 사라졌거나 검색이 실패했다고 느끼기 쉽다.
2. **다음 행동이 숨겨져 있다.** 업데이트 가능 배지가 보여도 주 버튼은 최신 확인이다.
   사용자는 상세 → 개요 → 준비 → 기록 → 검토 흐름을 스스로 찾아야 한다.
3. **경로·프로세스가 홈을 차지한다.** 같은 Codex의 여러 PID와 긴 파일 경로가
   반복되어 업데이트나 작업 상태보다 먼저 눈에 들어온다.
4. **상태와 행동이 떨어져 있다.** 자동화 사용 안 함, 실행 중 세션 수는 보이지만
   해당 설정·세션으로 직접 이동하지 못하고 상세 탭을 다시 찾아야 한다.

## 제안 범위

- 홈 상단: 업데이트 가능 / 진행 중 작업 / 실행 중 세션을 작은 요약으로 표시.
  실제 스냅샷에 근거한 수치만 쓰고 조회 미완료를 0으로 단정하지 않는다.
- 업데이트 관리 대상: CLI 이름, 현재 → 확인된 최신 버전, 실행 세션, 자동화 상태를
  한 줄로 묶는다. 설치 경로는 상세 정보로 이동한다.
- 주 버튼: 상태에 따라 최신 확인 / 업데이트 준비 / 준비 결과 확인으로 연결한다.
  최종 실행 승인과 기존 차단 조건은 유지한다. 새 자동 실행은 추가하지 않는다.
- 실행 세션 수와 자동화 상태를 해당 상세 탭으로 바로 연결한다.
- 관찰만 가능한 실행은 CLI별로 묶어 Codex · 3개처럼 표시한다. PID·전체 경로·
  터미널별 버전은 터미널 세션에서 확인한다. 묶음 표시를 설치 소유권 증명으로 쓰지 않는다.
- 대시보드 제목은 업데이트 관리 대상으로 바꾸고 카탈로그의 발견된 설치와 구분한다.
  전체 설치를 보려면 CLI 설치로 바로 이동할 수 있게 한다.

## 성공 기준

처음 방문한 사용자가 업데이트 가능한 CLI와 다음 행동을 홈에서 찾을 수 있고,
세션·자동화에 한 번의 선택으로 도달한다. 같은 CLI의 PID 반복 때문에 홈이
길어지지 않으며, 상세를 열지 않아도 지원 범위의 차이를 이해할 수 있어야 한다.
실행 버전/디스크 버전 구분과 미확인 상태, 확인 후 실행 절차는 보존한다.

## 범위 밖

업데이트 엔진, 지원 CLI 확대, 실제 CLI 업데이트, 자동 정책 변경은 포함하지 않는다.
추가 요청에 따라 동일 실행 경로에 대한 표시 전용 연결을 보완하되, 카탈로그 연결을
업데이트·삭제 권한으로 승격하지 않는다. 별도 앱/확장 프로그램과 전역 설치는 합치지 않는다.
