FEATURES

Updates first.
Evidence always.

Updates, Terminal sessions, and History keep installation changes, running processes, and verified results separate.

01 / UPDATES

Review the installation you will change.

Start with installed and checked latest versions and the check time. Review the exact executable and source before confirming. Execution uses the official latest release at that time, then verifies the actual installed result.

Add CLI opens from Updates. CLI details separate installation management, update target, terminal default and automation. A failed lookup is not “up to date”; source or platform restrictions explain the next step.

02 / SESSIONS

Installation is not session adoption.

Terminal sessions shows running and launch evidence separately from the disk version. Unknown evidence stays unknown. Updating the installation does not prove that an existing conversation runs the new version.

Restart is a separate, guarded action only for supported managed sessions or verified herdr panes. Upstream Pi, OpenCode and GJC do not offer same-conversation restart. Sessions outside herdr remain observation-only.

03 / HISTORY

Recover evidence, not an old command.

History retains individual successes, failures and uncertain outcomes. Recheck without reinstalling inspects source and disk version without an installation command. Missing execution evidence keeps the earlier result uncertain.

After fresh checks, archive an unverified outcome separately. Archived-unverified is not success. Active installation work blocks recovery; reload never replays an approval. Bulk results keep completed items separate from those needing attention.

04 / DETAILS

Keep source and policy explicit.

Management covers OmO, Pi, OMP, OpenCode, Claude Code, Codex and GJC. Pi means upstream @earendil-works/pi-coding-agent, not Senpi. Existing Senpi installations and conversations are preserved; standalone Senpi remains terminal-only.

New automation policies keep sessions; existing explicit and legacy policies retain their recorded behavior. Only an available newer version triggers catalog automation, not failed or incomparable checks. Installation, update and removal each require their own source checks. Other herdr sessions have no updater controls.
