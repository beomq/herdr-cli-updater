BEFORE YOU START

Check your environment.

Use Bun 1.4.2 or newer ↗ and Node.js 24 or newer ↗. The initial supported original-installation update target is OmO installed globally with Bun on macOS.

macOS and Linux use a POSIX terminal. Windows requires an existing WSL2 Linux distribution; install Bun and Node inside WSL. The app does not manage native Windows installations from WSL. Linux execution has not yet been verified end to end.

bun --version
node --version

The catalog includes additional tools, but installation, process visibility, and automatic updates have different support scopes.

02 / OPEN YOUR WORKSPACE

One command. Your local dashboard.

"$HOME/.local/bin/cli-updater"

On macOS, the app opens your browser with a one-time access link. On other systems, open the printed URL yourself. The service binds to 127.0.0.1 and stays running when you close the browser.

Prefer the shorter cli-updater command?

Add this line to your shell configuration, or run it in the current terminal:

export PATH="$HOME/.local/bin:$PATH"

Then run cli-updater. Do not install the app into the OmO global folder just to get a shorter command.

Check service status

"$HOME/.local/bin/cli-updater" status

Stop the service normally

"$HOME/.local/bin/cli-updater" stop

Automatic checks and updates are off until you enable them. They require the service to remain running. Active work can prevent a normal stop; check its state rather than forcing termination.

03 / TAKE A LOOK AROUND

Start with Updates, then decide.

  1. Updates

    Compare installed and checked latest versions, then review the exact target and source before execution. Add CLI opens here; CLI details separates management, update target, terminal default and automation. New automation keeps sessions; existing policies retain their saved behavior.

  2. Terminal sessions

    Inspect running and launch evidence independently from installed versions. Installation success is not session adoption. Restart needs separate support and review; upstream Pi, OpenCode and GJC do not offer same-conversation restart.

  3. History

    Inspect each result. Recheck an uncertain update without installing; archive-unverified remains unverified, not successful. Reload does not repeat an installer or approval.

WHEN SOMETHING IS UNCLEAR

A few useful answers.

The download or installation failed.

Check your network connection and Bun / Node versions, then run the installer again. A failed installation does not replace the previous active release. If ~/.local/bin/cli-updater already belongs to another installation, the installer stops instead of overwriting it.

The access link expired.

Run the app command again for a fresh one-time local link. Do not share the access URL or its token.

A CLI is installed, but cannot be updated or removed.

Discovery does not prove management authority. Updates require a supported installation owner. Direct removal covers app-owned installs and verified npm/Bun global packages; other methods use the CLI’s official instructions.

A running CLI has an unknown version or no installation link.

Old processes may still run old code after disk files change. The app does not substitute disk versions for missing launch evidence. A bundled tool, different install path, or unresolved launch path can remain unlinked.
